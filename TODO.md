  **Two real bugs found and fixed while testing against a real external project (not SDK-specific; every flavour had them):**
  - `ensure_container`'s `docker run -v ...` and `ensure_images`'s `docker build -f/context` passed Bash's own POSIX-style paths straight to `docker.exe`. Docker Desktop's CLI happens to auto-translate `/<drive>/...`-style paths, which is the only kind every path in this repo had used so far, so the bug was latent; a project under Git Bash's `/tmp` (a virtual mapping with no drive-letter relationship at all) bind-mounted as an *empty* directory with no error. Fixed with a new `to_native_path` helper (`cygpath -w` when available, no-op otherwise) applied everywhere a host path reaches `docker`.
  - The same problem hit `run-project.sh` independently: `$ELF` (from `find_elf`, also POSIX-style) was passed straight to PCSX2, a native program. PCSX2 doesn't auto-translate anything; it printed `Requested boot ELF '/tmp/...'` and refused to boot (CRC 0000000). Fixed the same way, and also applied it to `build-project.sh`'s `IMPRESSION_ELF=` output so that line is a genuinely native path for any consumer (a GUI, PCSX2 itself), not just something Bash's own later reuse happened to tolerate. (PowerShell was never affected: `Resolve-Path` already returns native paths.)
  - Minor, unrelated, not fixed: `pkill` is not present in this Git Bash install, so `run-project.sh --restart`'s kill step silently does nothing (caught by its own `|| true`, non-fatal, just doesn't restart the emulator).
  **Found, and NOT a bug in this project:** PCSX2 2.6.3's `host:` driver fails to boot an ELF (loads it, gets a real CRC, then a PC=0/CPU-fault loop, never reaching "is executing") when the ELF's path is very long/deeply nested — reproduced with a plain, already-known-good `project.elf` copied to a 192-character path (failed) versus a 57-character path (worked); the exact threshold was not bisected. Not a PS2SDK/Impression bug, but directly relevant to the SDK flavor's promise that a project can live anywhere: document it (keep project paths reasonably short, particularly on Windows) once the SDK flavor has user-facing docs.

- [x] **Real-time program output.** Done with the IMP_LOG layer (`inc/impression/log.hpp`, `src/log*.cpp`). Root cause of the lost output: on this toolchain and PCSX2 2.6.3 libc's `printf` never reaches PCSX2's console (a pure ps2sdk ELF behaves the same, so Tyra's IOP reset is not the cause), while the EE serial port (`sio_write`) is live. The layer writes every line to serial and to a buffered `bin/log.txt`, and overrides libc's `_write` (it used to assign the `_ps2sdk_write` pointer, which is a plain function in current ps2sdk) so Tyra's own `TYRA_LOG` output reaches both sinks too (verified in `examples/hello`, including after Tyra's `Engine` resets the IOP). Ruled out: [ps2dev/ps2sdk#332](https://github.com/ps2dev/ps2sdk/issues/332) was a PCSX2 bug fixed in 2022 ([PCSX2/pcsx2#7007](https://github.com/PCSX2/pcsx2/pull/7007)).
